# Doka Sentry and Cloudflare setup

Last reviewed: 2026-10-01

## Sentry: use React/Vite, not Next.js

The Doka frontend is React 19 + Vite 7. It is not a Next.js application. Do not run:

`npx @sentry/wizard@latest -i nextjs ...`

That wizard targets Next.js 14+ and will create Next-specific configuration that does not belong in this repository.

The backend already has an opt-in FastAPI Sentry integration in `app/core/observability.py`. The personal backend requirements include `sentry-sdk[fastapi]`. Sentry remains disabled until `SENTRY_DSN` is configured. Events are scrubbed to remove request bodies, cookies, non-allowlisted headers, URLs/query strings, exception messages, stack-frame locals/source paths, log messages, arbitrary tags, user identity, breadcrumbs, contexts, and custom extras.

### Create the Sentry project

1. Sign in to Sentry.
2. Use the Sentry organization slug `enterprise-ai-dms` supplied for this Doka setup (if Sentry confirms that slug exists in the account).
3. Create a new project and choose **React** (or Browser JavaScript if React is not offered). Name it `doka-frontend`.
4. Copy its DSN. The DSN is safe to expose to the browser, but keep it in Vercel Environment Variables rather than hardcoding it.
5. Create a second project named `doka-api` using the Python/FastAPI platform and copy its DSN separately.

Do not use the supplied `reactNative` wizard command or create a React Native project for Doka. The Doka frontend is browser React/Vite. Do not reuse a Next.js project created for another app unless it is intentionally repurposed and its platform/configuration is corrected.

### Frontend SDK work

The Vite frontend needs the `@sentry/react` SDK, an initialization module imported before the app, and an error-boundary capture hook. Configure it only when `VITE_SENTRY_DSN` is present. Keep tracing and Session Replay disabled initially; Doka handles private document names and OCR content, so do not enable Replay or send DOM/document content without a separate privacy review.

The current repository's npm lockfile must be regenerated by npm after adding `@sentry/react`; do not hand-edit `package-lock.json`. The connected repository editor cannot run npm or resolve packages, so this SDK addition is still pending. After adding the SDK in an npm-enabled checkout, run `npm install`, `npm ci`, `npm run build`, and the frontend smoke tests.

### Vercel values

After frontend SDK code is committed, set:

- `VITE_SENTRY_DSN=<doka-frontend DSN>`

For source-map uploads only, add `SENTRY_AUTH_TOKEN` as a server-side Vercel build environment variable. Use a narrowly scoped Sentry token with project/release write permissions. Never prefix this token with `VITE_`, never put it in browser code, and never commit it.

### Python API host values

Once the remote Python API host is selected, set server-side:

- `SENTRY_DSN=<doka-api DSN>`
- `ENVIRONMENT=production`

Do not set `SENTRY_DSN` in the browser bundle. Local backend development can use the same setting in its ignored local `.env` file if desired.

### Verify safely

1. Deploy the SDK-enabled frontend and backend.
2. Use a temporary, explicit test action that throws a harmless synthetic error (not an error containing a document name, file path, OCR text, token, or real user data).
3. Confirm one issue appears in the correct Sentry project.
4. Remove/disable the test action immediately after verification.
5. Check that the event has no request body, cookies, auth headers, URL/query, user identity, document data, or filesystem path.

## Cloudflare R2: setup is optional and billing-gated

Doka already has a private Supabase Storage bucket. Do not migrate real documents to R2 until the API host is selected and authenticated R2 upload/download tests pass.

Cloudflare's current R2 onboarding requires completing an R2 subscription checkout before generating R2 API credentials. R2 has a free monthly allowance, but it is a metered service and usage beyond the allowance is billable. If Cloudflare asks for a payment method or paid subscription activation and the user wants to keep a strict no-card/no-billing setup, stop and continue using Supabase Storage. Do not complete checkout on the user's behalf.

### If the account can enable R2 without violating the free-only requirement

1. Open Cloudflare Dashboard → Storage & databases → R2 Object Storage → Overview.
2. If activation proceeds without adding a payment method or enabling paid billing, create a Standard storage bucket named `doka-private-documents`.
3. Keep it private; do not enable public bucket access or a public custom domain.
4. Under Manage R2 API Tokens, create a token with **Object Read & Write** permission, restricted to this bucket only.
5. Save the Access Key ID and Secret Access Key in a password manager. The Secret Access Key is shown only once.
6. Copy the Account ID and S3 endpoint, normally `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`.
7. Do not paste credentials into chat, GitHub, Supabase SQL, or Vercel `VITE_*` variables.

When the Python API host is ready, set server-side only:

- `DOKA_STORAGE_PROVIDER=r2`
- `R2_BUCKET=doka-private-documents`
- `R2_ENDPOINT_URL=https://<ACCOUNT_ID>.r2.cloudflarestorage.com`
- `R2_ACCESS_KEY_ID=<Access Key ID>`
- `R2_SECRET_ACCESS_KEY=<Secret Access Key>`

Use a quota guard and usage alerts before storing real files. Cloudflare's published Standard free allowance is 10 GB-month storage, 1 million Class A requests, and 10 million Class B requests monthly; internet egress is free. Anything beyond included usage can be billed. Review current pricing before enabling it.

## Remaining Doka platform work

- Select a free/no-card Python API runtime that supports FastAPI and the required OCR workload.
- Vercel's public Supabase URL and publishable key are already present in the compiled frontend bundle. The `/admin/cloud-documents` page now calls Supabase PostgREST/Storage directly; it does not require `VITE_API_BASE_URL`.
- Complete a real signed-in upload/download and cross-user isolation E2E test for the direct Supabase browser flow.
- Select a free/no-card Python runtime only for remote OCR, extraction, and workspace processing; set `VITE_API_BASE_URL` only when that API is actually deployed and routed.
- Complete frontend Sentry React SDK integration and source-map upload configuration.
- Configure the backend Sentry DSN on the selected API host.
- Keep R2 inactive unless the user confirms activation can be done without card/payment requirements.
- Confirm latest GitHub Actions and Vercel production deployment before browser E2E.
