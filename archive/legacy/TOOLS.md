# Doka Tools, Services and Operational Boundaries

Last reconciled: 2026-10-07

This document describes the tools/services Doka may use and the boundary each one must respect. A service being configured or present in the repository does not mean the feature is production-ready.

## 1. Development and repository tools

| Tool | Role | Boundary |
|---|---|---|
| Git/GitHub | Source control, review, CI evidence | Repository writes are not runtime verification |
| Python 3.12 | Personal Local backend/runtime | Required for local FastAPI |
| Node.js 24.x | React/Vite frontend | Required for current frontend tooling |
| Tesseract OCR | Local Myanmar/English OCR | Requires representative validation and resource limits |
| npm | Frontend dependencies/build | Lockfile changes must be generated by npm |

## 2. Runtime services

### Personal Local
FastAPI + Python, React + Vite, local filesystem workspace, local SQLite-compatible state, Tesseract OCR, and optional AI disabled by default. It must work without cloud infrastructure.

### Personal Cloud
Supabase Auth, Supabase Postgres + RLS, private Supabase Storage during transition, Cloudflare Worker as the active cloud API, and Cloudinary as the selected later private object-storage target.

Cloud credentials and server secrets must remain outside browser bundles.

## 3. Deployment tools

Current live environment inventory and provider/key ownership are tracked in `docs/ENVIRONMENT_MATRIX.md`. AI routing and agent boundaries are tracked in `docs/AI_PROVIDER_MATRIX.md`.

### Vercel
Frontend hosting target only. Production is intentionally paused/owner-controlled. Do not reactivate, reconnect, or trigger production deployment without explicit authorization. CI success does not prove production deployment readiness.

### Cloudflare
Active Worker API for cloud documents. The Worker must not unnecessarily proxy large document bytes. Authentication/ownership remains enforced by Supabase Auth plus RLS/Storage policies. Verify live deployment evidence before calling a Worker change production-live.

### Supabase
Auth identity/session boundary for Cloud, Postgres metadata and RLS, and private Storage transition path. The remaining known Security Advisor warning is leaked-password protection; it requires explicit dashboard/configuration verification.

### Cloudinary
Selected private object-storage target for Cloud Edition. Do not migrate real data until provider configuration, quota behavior, cleanup, and recovery are tested.

## 4. Data and processing tools

### OCR
Local OCR is the first supported processing path for Personal Local. Myanmar and English quality must be measured on representative copied data.

### AI
Disabled by default. External processing requires explicit consent in addition to AI enablement. AI recommendations remain advisory. AI must not perform destructive filesystem operations without explicit human approval. Provider/model/failure metadata should remain provider-neutral.

### Backup/Recovery
Local backups contain integrity manifests. Restore is recovery-only and must use an isolated destination. Cloud recovery requires real provider drills before production sign-off.

## 5. Remote office access

Use a private VPN/secure tunnel such as Tailscale when remote browser access is required. Do not expose the local FastAPI server or original source drive through public port forwarding.

## 6. Verification evidence

For every operational tool/service distinguish code-level implementation, automated CI result, live-service configuration, real-browser result, and real-machine/copied-data result. Never convert an unavailable or skipped check into a passing result.
